## Why

Permissions are global per role (Analysts cannot view dashboards), public links never expire, every digest runs every 15 minutes, and alerts re-fire on every check.

## What users get

Share each dashboard with the right people, links that expire, and alerts that fire once.

## Target specs

"Today" is `main` at `47a826d`, read from the code, not tested. A target is either a competitor's documented number (named under Benchmark) or marked *(proposed)*: the planner's number, which the product owner confirms or changes on the feature page before the plan is written.

| Capability | Today | Target |
| --- | --- | --- |
| Permissions | Global per role only | Per dashboard and folder: view, edit, manage; inherited from the folder |
| Public links | No expiry, no password | Expiry (required, default 30 days, proposed) and an optional password; revocable |
| Digests | Every digest every 15 minutes | Each has its own schedule (as RPT-1) |
| Alerts | One aggregate over a whole table; re-fires every check | On any chart or metric, with filters; conditions: goes above/below, any result; fire once per crossing, then on recovery |
| Chart image | None | PNG download of a chart |
| Comments | None | Comments on a dashboard, with mentions that notify |
| Import | YAML export only | Import an exported dashboard, mapping its tables |

## Benchmark

Metabase: collection permissions (view, curate), public links, alerts on goal and results (all plans). Tableau: project permissions.

## Acceptance checklist

Run on a running console by the product owner. A step not performed is never a pass.

- `BI-19-AC1` An Analyst given view on one dashboard sees it and nothing else
- `BI-19-AC2` A public link stops working after its expiry
- `BI-19-AC3` An alert fires once when crossing the threshold, not every check
- `BI-19-AC4` A user without the permission is refused, and a failure shows an honest message (principles 2 and 4)

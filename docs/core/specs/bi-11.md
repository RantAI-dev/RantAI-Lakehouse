## Why

Charts and dashboards cannot take a value the viewer chooses other than a filter.

## What users get

Let viewers pick a value (a target, a measure, a top-N) that changes charts.

## Target specs

"Today" is `main` at `47a826d`, read from the code, not tested. A target is either a competitor's documented number (named under Benchmark) or marked *(proposed)*: the planner's number, which the product owner confirms or changes on the feature page before the plan is written.

| Capability | Today | Target |
| --- | --- | --- |
| Parameter types | None | Number, text, date, and a list of allowed values |
| Uses | None | In formulas (BI-8), top-N, reference lines, and to switch the measure or dimension shown |
| On the dashboard | None | A control like a filter; value kept in the URL |
| In SQL | None | Through QS-5 named parameters, bound, never spliced |

## Benchmark

Tableau parameters and parameter actions. Metabase SQL variables.

## Acceptance checklist

Run on a running console by the product owner. A step not performed is never a pass.

- [ ] Every Target row above works as written
- [ ] A 'top N' parameter set to 5 shows the top 5 on every linked chart
- [ ] Switching a measure parameter from revenue to visitors changes the chart
- [ ] A user without the permission is refused, and a failure shows an honest message (principles 2 and 4)

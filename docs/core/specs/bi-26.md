## Why

A single-chart embed shows the whole board if a parameter is removed, branding is hard-coded, filters pass only as locked token values, and sizing is fixed.

## What users get

Embed one chart or a dashboard that fits the host page and its look.

## Target specs

"Today" is `main` at `47a826d`, read from the code, not tested. A target is either a competitor's documented number (named under Benchmark) or marked *(proposed)*: the planner's number, which the product owner confirms or changes on the feature page before the plan is written.

| Capability | Today | Target |
| --- | --- | --- |
| Single-chart embed | Removing a URL parameter shows the whole board | The token names the chart; nothing else can be shown |
| Look | 'Rantai Lake' hard-coded | Light/dark theme, optional logo or none, background transparent option |
| Filters | Locked filters in signed tokens only | Locked (in the token), editable (shown to the viewer) or hidden, per filter (Metabase) |
| Sizing | Fixed | Height follows content (resize messages to the host page) |
| Security | See SEC-12 | Expiry, revocation, frame-ancestors allowlist |

## Benchmark

Metabase guest embeds: dashboards and questions, locked and editable parameters, theme, auto-resize. Tableau Embedding API. We stop short of an SDK (owner decision).

## Acceptance checklist

Run on a running console by the product owner. A step not performed is never a pass.

- `BI-26-AC1` A chart embed cannot be turned into a dashboard by editing the URL
- `BI-26-AC2` An embed's height matches its content in the host page
- `BI-26-AC3` A locked filter cannot be changed by the viewer
- `BI-26-AC4` A user without the permission is refused, and a failure shows an honest message (principles 2 and 4)

## Not included

- An embedding SDK or React components (owner decision)

## Why

The assistant changes dashboards for the person. A change it makes that is wrong has to come back in one step, and the dashboard's version history already holds the board before each change.

## Target

| Capability | Today | Target |
| --- | --- | --- |
| Undo the assistant's last change to a dashboard | Not possible | One chat turn, after a confirm: "undo that" takes the board back to before the assistant's change |
| Undo a change someone else made, or the person's own manual edit | n/a | Refused, with a sentence pointing to Versions in the dashboard menu |
| Undo a metric, calculated field, parameter, alert or cache rule | n/a | Not in the history; refused in chat, said plainly |
| Versions written before this release | n/a | Cannot be undone by the assistant; the refusal says so |

## Decisions (owner, 2026-11-27)

1. One tool, `undo_last_change { board }`, a confirm (`WriteLow`). It restores through the console's own revert logic, as the signed-in person, so edit on the board is checked there.
2. A change by someone else is never undone. The walk stops at it and refuses.
3. Scope is board content only: charts, layout, filters, tabs and the theme.
4. One step per call. A second undo goes one assistant change further back, not a redo of the first.
5. The prompt size may rise by 1,500 characters or less per prompt variant.

Decision 2 holds through the author check, because a version's author is the signed-in person for every change (the assistant acts as them), not "Assistant". The assistant's board writes therefore carry a label, `Assistant: <what changed>`, that the history reads. This is the only marker: the store and its schema are unchanged.

## How it works

- The assistant's board writes (the tool call sites only, never the console routes) label their version `Assistant: <what changed>`.
- An undo walks the versions from the newest. It skips the requester's earlier undos (labelled `Assistant undo of v<n>`) and the versions they named. The first other version must carry the assistant's label and be the requester's; otherwise the undo refuses.
- The undo reverts to the version just before that target, through the console's revert logic. The restore is labelled `Assistant undo of v<target>`.
- Versions written before this release carry no label. They cannot be undone, and the refusal says so.

## Acceptance

- `AI-21-AC1`: "undo that" after the assistant changed a chart restores it, after a confirm.
- `AI-21-AC2`: a person's later edit, or the person's own manual edit, is never reverted: the undo refuses and changes nothing.
- `AI-21-AC3`: undo of a metric is refused with the scope sentence.
- `AI-21-AC4`: a second undo goes back one more assistant change, not a redo.

## Why

Fixing a failing query is the most common reason to ask for help in Query Studio.

## What users get

Fix, explain and improve SQL without leaving the editor.

## A user says

> Why does this query fail? Fix it.

## Target specs

"Today" is `main` at `47a826d`, read from the code, not tested. A target is either a competitor's documented number (named under Benchmark) or marked *(proposed)*: the planner's number, which the product owner confirms or changes on the feature page before the plan is written.

| Capability | Today | Target |
| --- | --- | --- |
| Open from the editor | Not possible | With the current SQL and the error |
| Fix | n/a | Proposes a change shown as a diff the user accepts or rejects; never runs it unasked |
| Explain | n/a | Explains a query in plain words |
| Permissions | n/a | Runs through the same masking as Query Studio (SEC-9) |

For every capability: The assistant uses the same API and permissions as the user; anything that deletes, shares or publishes asks for approval first.

Note: Variables wait for QS-5 (Query Studio).

## Benchmark

Databricks: quick fix, diagnose error, optimize in the editor. Snowflake Cortex Code: generate, fix, explain.

## Acceptance checklist

Run on a running console by the product owner. A step not performed is never a pass.

- `AI-12-AC1` The quoted request on a query with a misspelled column proposes the right column as a diff

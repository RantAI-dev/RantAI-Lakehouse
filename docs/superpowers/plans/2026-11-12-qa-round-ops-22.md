## 0. What the reading established

### 0.1 How the test processes share one Postgres

- Every test binary that links `lakehouse-test-support` runs its constructor before `main`
  (`lib.rs:541-544` → `start_postgres_container`, `:217`). It finds or starts **one labelled
  container per Docker daemon** (`with_label("org.rantai.lakehouse-test-support",
  "postgres-16-shm1g")` `:289`, `ReuseDirective::Always` `:290`; `testcontainers` 0.27.3
  looks a reusable container up by its labels, `runners/async_runner.rs:93-137`), waits for
  it, runs the **first sweep pass** (`start_sweep`, `:321`, `:469-479`) and sets
  `DATABASE_URL` (`:313`, the `postgres` database).
- CI: job `test` (`.github/workflows/ci.yml:376-392`) is three jobs, one runner each, so one
  container per partition. Each runs `cargo nextest run --workspace --locked --profile ci
  --color never --partition "count:N/3"` (`ci.yml:486-490`). The `ci` profile
  (`rust/.config/nextest.toml`) sets `slow-timeout`, `fail-fast = false` and the junit path.
  It has **no test group, no `threads-required`, no `retries`**.
- `cargo nextest` runs **every test in a process of its own**, several at once. The failing
  test's own output shows it: "running 1 test … 7 filtered out". So every test of a binary
  that links this crate runs the constructor and one first pass of its own.
- The sweep's state is **in the memory of the process**: `Sweeper::idle_seen_last_pass`
  (`:382`), a new empty set per `Sweeper::new()` (`:387-391`). There is no table, file or
  lock in the cluster. Passes of two processes never add up.
- The repeating pass (`spawn_sweep_loop`, `:486-499`) sleeps `SWEEP_INTERVAL` = 30 s before
  every pass (`:489`, `:493`). It is compiled out of this crate's own test binary
  (`#[cfg(not(test))]`, `:477`, `:486`) and runs in every other test process. So outside this
  crate's tests, one process's two sightings of a database are **at least 30 s apart**, and a
  process that ends before 30 s (most nextest processes) drops nothing.
- `Sweeper::pass` itself (`:407-465`) has **no minimum age and no minimum time between
  passes**. The 30 s is only the caller's sleep. `pg_database` has no creation time.

### 0.2 The defect: this crate's own tests sweep the whole server twice within milliseconds

Four tests build `Sweeper::new()` and call `pass` twice with nothing in between (`:751-759`,
`:797-805`, `:834-842`, `:867-875`; a fifth, `:917-921`, runs one pass). Their sweeper has the
production rule (`is_sweepable(&name) && !busy`, `:433`): **every** database on the server
with one of the three prefixes and no backend at both listings is dropped (`:441-463`), a few
milliseconds after it was first seen.

The tests were kept apart by a turn token, `static TURN: AtomicBool` (`:567`, `take_turn`
`:580-590`). It is a static of the process. Under `cargo test` (one process, tests on
threads) it worked. Under nextest every test is a process, so **the token serialises
nothing**, and the module doc's "The tests of this crate therefore take a turn" (`:115-117`)
has been false in CI since `REL-20`.

## 1. Decisions

- **D1. One design: a sweeper built by a test looks only at the databases that test
  created.** `Sweeper` gets a scope: `None` is every database on the server (the sweep of a
  test process, as today), `Some(names)` is exactly these names. `Sweeper::only(names)`
  exists under `#[cfg(test)]` only. Reason: the two passes with no time between them are the
  whole defect, and they exist only in these tests. With the scope, no test can drop another
  test's database (symptom b), and no other test of this crate can drop this test's
  databases (symptom a). It is the smallest change that removes both.
- **D2. The sweep of a test process does not change.** `start_sweep` keeps `Sweeper::new()`:
  all three prefixes, the whole server, 30 s between passes. Leftover databases of killed
  runs are still dropped (`OPS-13`). The tests keep the three real prefixes for their own
  databases, so a database a killed test of this crate leaves behind is still swept by other
  processes. A private prefix was rejected for that reason.
- **D3. Rejected.** (1) A minimum age or spacing inside `pass`: the tests would need a way
  round it, and that way round would have to be the scope of D1 anyway. (2) An advisory lock
  held by the owner: sqlx creates the databases, not this crate. (3) A nextest test group or
  `retries`: it would hide symptom (a) in CI only and leave symptom (b) and local runs as
  they are; a retry is forbidden (rule 2).
- **D4. What the sweep tests assert (rule 2: the old assertion was wrong, not inconvenient).**
  After D1, the only thing besides the test's own sweeper that can drop its database is the
  repeating sweep of another process, and that needs two sightings `SWEEP_INTERVAL` apart
  (0.1). So:
  - "after two passes the database is **gone**" is always true and stays unconditional;
  - "this sweeper **picked** it" and "an idle database this sweeper may not touch still
    **exists**" are true as long as the database is younger than `SWEEP_INTERVAL`. The tests
    assert them exactly so: unconditionally while the test has run for less than
    `SWEEP_INTERVAL` since before it created its first database, and not at all after that,
    with a line on stderr saying the assertion was not made and why (principle 2);
  - what this sweeper did **not** pick (`!candidates.contains`, `candidates.is_empty()`) is
    its own decision, no other process can change it, and stays unconditional.
  In practice a test body takes under a second, so every assertion is made every time.
- **D5. The turn token goes.** With D1 the tests cannot drop each other's databases, in
  threads or in processes, so `TURN`, `TurnGuard` and `take_turn` are removed and
  `cargo test` runs the tests in parallel. That is also a check of D1 on every local run.
- **D6. Measured before and after (principle 5), on a private container.** The machine is
  shared, and a loop of today's tests would drop the databases of other workers' running
  tests on the shared container. The developer measures under a temporary, never committed
  label (section 3.1).
- **D7. No document edit by the developer** except the handoff in this file. The planner
  updates the `OPS-22` row after the merge.

   ```rust
   /// A sweeper that looks only at the databases with these names.
   ///
   /// `OPS-22`: this crate's tests run two passes with no time between
   /// them. With the server-wide rule those two passes dropped every test
   /// database on the shared server that had no backend at that instant:
   /// the databases of the other tests of this binary (CI runs 43250741080,
   /// 43344075791, 43349333080) and the database of a running
   /// `#[sqlx::test]` of another binary (CI run 43033910245). `cargo
   /// nextest` gives every test a process of its own, so an in-process
   /// turn token cannot keep them apart. A test's sweeper is therefore
   /// given the names the test created and never sees another database.
   #[cfg(test)]
   fn only(names: &[&str]) -> Self {
       Self {
           idle_seen_last_pass: BTreeSet::new(),
           only: Some(names.iter().map(|name| (*name).to_owned()).collect()),
       }
   }

   /// Whether this sweeper may look at the database with this name.
   fn in_scope(&self, name: &str) -> bool {
       match &self.only {
           None => true,
           Some(names) => names.contains(name),
       }
   }
   ```

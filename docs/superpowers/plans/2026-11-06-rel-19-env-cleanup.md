# REL-19 (with REL-18): a short `.env.example`, PDF export on by default

Backlog `REL-19` and `REL-18` (P2, Delivery). Planner: Claude Opus, 2026-11-06.
Anchors verified at `main` `d2b26f45`. Base branch: `main`. Feature page:
`docs/core/features/console-settings.md`. Developer: DeepSeek (opencode).
One PR.

## 0. What is wrong

- `.env.example` has 187 settings (139 set, 49 commented). An operator cannot tell the
  five they must think about from the 180 they should never touch.
- Most are internal wiring (database names, service addresses), tuning whose default is
  already in code or compose, or test-only values.
- `CONSOLE_INTERNAL_URL` is empty in `.env.example:200` and `docker-compose.yml:412`
  (`${CONSOLE_INTERNAL_URL:-}`), so PDF export and PDF report attachments are off on a
  fresh install (`REL-18`). Gotenberg's allow-list reads the same variable
  (`docker-compose.yml:1140`).

## 1. Decisions

- **D1. Nothing behaves differently.** For every line removed from `.env.example`, the
  value a fresh install gets must stay the same. Proof (task T1 builds it, T6 runs it):
  `docker compose --env-file <old>.env --profile '*' config` and the same with the new
  file, with the same generated secrets in both, give identical output except for the
  `CONSOLE_INTERNAL_URL` change of D4. When a removed line set a value that differs from
  compose's `${X:-default}`, compose's default is changed to that value, with the reason
  in the comment.
- **D2. What stays visible in `.env.example`** (about 25 set lines), in this order:
  1. **Generated by the installer**, empty here: `POSTGRES_PASSWORD`,
     `CONNECTOR_SECRETS_KEY`, `LAKEKEEPER_ENCRYPTION_KEY`, `RUSTFS_ACCESS_KEY`,
     `RUSTFS_SECRET_KEY`, `SEAWEEDFS_*`, `AUTH_BOOTSTRAP_PASSWORD`,
     `RENDER_TOKEN_SECRET`, the tenant warehouse pair, and every other value
     `ops/init-env.sh` or `lakehousectl` (`rust/crates/lakehousectl/src/env.rs`) writes.
     Grep both; any secret either generates stays as an empty line here.
  2. **Your choices**: `AUTH_BOOTSTRAP_EMAIL`, `CATALOG_TENANT_ID`, `CONSOLE_PUBLIC_URL`,
     the published ports an operator may need to move, `BACKUP_RETENTION_DAYS`.
- **D3. Commented feature blocks**, each a short heading, one line on what it turns on,
  and its settings commented out with their defaults: Email (`SMTP_*`), Assistant
  (`LLM_*`), Single sign-on (`OIDC_*`), Secret managers (`VAULT_*`, `AWS_*`, `AZURE_*`,
  `GOOGLE_APPLICATION_CREDENTIALS`, `SECRET_MANAGER*`), Backups to S3 (`BACKUP_S3_*`),
  Tenant storage on outside S3 (`TENANT_*`), Networks you allow (`*_ALLOWED_CIDRS`,
  `*_ALLOW_INTERNAL_HOSTS`, off). Each block ends with "Every setting:
  docs/CONFIGURATION.md#<anchor>".
- **D4. `REL-18`: PDF export on by default.** `docker-compose.yml:412` and `:1140` become
  `${CONSOLE_INTERNAL_URL:-http://console:3000}` (empty and unset both mean the console
  service, so an install that copied the old empty line gets PDFs after update too; this
  replaces the "empty means off" wording in the backlog item: downloads are switched off
  per role with `downloadDeniedRoles`). `.env.example` drops the line. Fix the comments
  in compose (`:401-412`, `:1120-1126`), `.env.example:192-199` and
  `docs/OPERATIONS.md` ("Features unavailable in the local stack": the PDF row goes),
  and `docs/core/features/export-pdf-excel.md` "Switching it on".
- **D5. Removed entirely from `.env.example`** (still in `docs/CONFIGURATION.md`):
  tuning (`LOGIN_*`, `UPLOAD_*`, `AUTH_RETENTION_DAYS`, `AI_CHAT_TIMEOUT_SECS`,
  `EMBED_TOKEN_MAX_LIFETIME_SECONDS`, `OIDC_CLOCK_SKEW_SECONDS`, `TRINO_*`,
  `GOLD_EXPORT_MAX_ROWS`, `GOLD_EXPORT_BATCH_SIZE`, `INGEST_RETRY_DELAYS_SECONDS`, the
  `AI_*` feature switches), internal wiring (`DAGSTER_REPO`, `DAGSTER_LOCATION`,
  `*_PG_DB`, `POSTGRES_DB`, `CH_DB`, `LAKEHOUSE_WAREHOUSE_BUCKET`, `*_SECRET_REF`,
  internal `*_URL`s with a compose default).
- **D6. Test-only values** (`GOLD_MART_NAME`, `GOLD_EXPORT_ROW_COUNT`, `BRONZE_*`,
  `CONSOLE_ALLOWED_DEV_ORIGINS`, `APP_ENV`): grep `.github/workflows/`, `ops/g*`,
  `scripts/`. If a workflow or gate relies on `.env.example` carrying one, set it in that
  workflow's `env:` or the gate's script instead; list each move in the handoff. Document
  them in `docs/DEVELOPMENT.md`.
- **D7. `docs/CONFIGURATION.md`** keeps a row for every setting, and gains a column or
  marker "in `.env.example`: yes / commented / no". Nothing is deleted from it.
- **D8. Readers of `.env.example`** (`ops/init-env.sh`, `lakehousectl`, the release and
  staging workflows, `scripts/ci/detect_change_scope.sh` and its test, `scripts/*.sh`,
  `dagster/dispar_orchestrate/definitions.py`): each still works. If one parses a line
  that is removed, fix the reader, not by keeping the line.

## 3. Out of scope

Sizing limits from the host. `lakehousectl` keeping itself on the host.

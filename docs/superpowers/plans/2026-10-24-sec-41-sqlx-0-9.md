## Why

Read the spec first (`docs/core/specs/sec-41.md`): its decisions D1-D4
are signed by the product owner and are not reopened here. In short:
`sqlx-core` 0.8.6 cannot verify a CA when it dials an IP address (it only
knows rustls' `NotValidForName`, rustls 0.23 reports
`NotValidForNameContext`), so `SEC-14` part B (PR #192) cannot merge.
`sqlx` 0.9.0 is on crates.io (rust-version 1.94; we are on 1.99.1).

## What is true at `022e3608`

- `rust/Cargo.toml:61`: `sqlx = { version = "0.8", features =
  ["runtime-tokio-rustls", "postgres", "mysql", "uuid", "time", "json",
  "macros", "migrate"] }`. Users: `lakehouse-store`, `lakehouse-api`,
  `lakehouse-auth`, `lakehouse-test-support` (all `workspace = true`).
  Nothing outside our crates depends on `sqlx`.
- In 0.9 the feature `runtime-tokio-rustls` is gone: it is
  `runtime-tokio` plus a TLS feature (`tls-rustls` = `tls-rustls-ring` =
  `tls-rustls-ring-webpki`, which is what 0.8's `runtime-tokio-rustls`
  meant).
- No `query!` macros are used; there is no `.sqlx` offline directory.
  `sqlx::migrate!("../../migrations")` is used.
- About 100-160 call sites pass a run-time string to `sqlx::query*` /
  `raw_sql` / `execute` (`grep` estimate). In 0.9 every `query*()` takes
  `impl SqlSafeStr`; a `String` must be wrapped in
  `sqlx::AssertSqlSafe(..)`. The compiler finds them all.
- `rsa` today: `cargo tree -i rsa -e normal` shows `sqlx-mysql` 0.8.6
  (normal, so in the API binary) and `lakehouse-auth`'s dev-dependency.
  `rust/deny.toml:25-31` and `.github/workflows/security.yml:39-44` claim
  it is dev-only, which is false today (spec D3).
- MySQL dials: `rust/crates/lakehouse-api/src/connector_probe.rs:1161-1168`
  (`MySqlConnectOptions`, `MySqlSslMode::Preferred`); Postgres:
  `:1151` (`PgSslMode::Prefer`). `VerifyCa` itself is added by PR #192,
  not here.
- Other 0.9 breaking changes to check against our code (CHANGELOG of
  `sqlx` 0.9.0): `RawSql` gained a `DB` parameter and
  `fetch_optional` changed (#3613, #3924; we use `raw_sql` in
  `lakehouse-store/tests/governance.rs:271`, `identity.rs:538`);
  `PgConnectOptions::options()` now escapes (#3800; grep found no use);
  `impl Decode for Cow` always owns (#3674); `Arguments` lost its
  lifetime (#3960); the `tracing` field `aquired_after_secs` was renamed
  (#3486; check nothing parses it).

## Decisions (planner)

1. `rust/Cargo.toml`: `sqlx = { version = "0.9", default-features =
   false, features = ["runtime-tokio", "tls-rustls", "postgres", "mysql",
   "uuid", "time", "json", "macros", "migrate"] }`. `tls-rustls` (ring,
   webpki roots) is the same backend 0.8 used: no behaviour change in
   which roots or crypto provider a dial uses. `mysql-rsa` stays off
   (spec D3). Keep `default-features = false` only if `any` is unused; if
   something needs `any`, add it and say so. Rewrite the comment at
   `rust/Cargo.toml:9` that says `sqlx` 0.9 is still to come.
2. Lockfile: only what the upgrade needs moves (`sqlx*` 0.8.6 -> 0.9.0
   and their new or bumped dependencies). No unrelated `cargo update`. If
   the upgrade forces another of *our* direct dependencies to change
   version, stop and report.
3. `AssertSqlSafe` (spec D4): wrap each run-time string where it is
   passed, with a short comment on the same or previous line saying why
   it is safe ("identifiers are constants / validated by `X`; values are
   bound"). No helper that hides the reason. If a site is **not** safe
   (a value formatted into SQL), do not wrap it: stop and report it as a
   finding, with the file and line.
4. MySQL (spec D3): a MySQL server with no TLS that asks for
   `caching_sha2_password` full auth or `sha256_password` makes `sqlx`
   0.9 without `mysql-rsa` return an error. Find that error in
   `sqlx-mysql` 0.9.0's source and map it, where connector dials classify
   errors (`connector_probe.rs` and whatever classifies MySQL dial errors
   for discovery and listing), to one fixed sentence: "This MySQL server
   asks for its password over an unencrypted connection. Turn on TLS on
   the server, or use mysql_native_password for this user." Match on the
   error's type or kind; match on text only if `sqlx` gives nothing else,
   with a comment saying so. A unit test covers the mapping. Document the
   limit in `docs/core/features/` only through the planner (tell me
   where; do not edit `docs/core/`).
5. `rsa` (spec D3, AC3): after the upgrade `cargo tree -i rsa -e normal
   -p lakehouse-api` must be empty. `rsa` stays in `Cargo.lock` as
   `lakehouse-auth`'s dev-dependency, so the `RUSTSEC-2023-0071` ignore
   stays in `rust/deny.toml` and `.github/workflows/security.yml`; rewrite
   both comments so they are true (dev-only since `SEC-41`; before it the
   API binary linked it through `sqlx-mysql` 0.8). If `rsa` is gone from
   `Cargo.lock` entirely, remove the ignore in both files instead and say
   so.
6. Migrations (AC2): databases migrated by 0.8 must start under 0.9. A
   `sqlx::test`-style test in `lakehouse-store` (or `lakehouse-test-
   support`, whichever owns migration tests today; grep first) creates
   `_sqlx_migrations` with the DDL `sqlx-postgres` **0.8.6** uses (copy it
   from `~/.cargo/registry/src/*/sqlx-postgres-0.8.6/src/migrate.rs`,
   cite the file in a comment), applies each migration's SQL, inserts one
   row per migration as 0.8 writes it (version, description, success,
   checksum = SHA-384 of the file as 0.8 computes it, execution_time),
   then runs the 0.9 `MIGRATOR`: it must return `Ok` and add no row. If
   0.9 changed the table or the checksum so this fails, stop and report;
   do not "fix" it by rewriting rows.
7. CA check (AC1): `VerifyCa` is added to production code by PR #192, not
   here, so this PR proves the `sqlx` half with a test that uses
   `PgConnectOptions` directly: a test-only TLS terminator in front of
   the test Postgres (answer Postgres' `SSLRequest` with `S`, then
   rustls, then forward bytes), certificate issued by a test CA for a
   **name** (for example `db.internal`), dialled at `127.0.0.1` with
   `PgSslMode::VerifyCa` and that CA: it connects and `SELECT 1` works.
   The same dial with a different CA fails. PR #192 has such a terminator
   (`git show origin/fix/sec-14-part-b-tls:rust/crates/lakehouse-api/src/tls_proxy.rs`);
   you may copy what you need into a test-only module, citing it. A
   dev-dependency for certificates (`rcgen`, as #192 uses) is allowed.
   The test must fail on 0.8.6 for the first case: you do not have to
   prove that by downgrading, but say whether you saw it.

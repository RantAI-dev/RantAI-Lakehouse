# `SEC-81`: Next.js 16.4.3 → 16.4.6

Planner and reviewer: Claude Opus. Developer: Claude Sonnet. Base: `main`.
Branch: `chore/sec-81-next-16-4-6`.

## Why

`next` 16.4.3 (and `eslint-config-next` 16.4.3) is inside seven moderate
npm advisories, all fixed in 16.4.5 (list in the `SEC-81` backlog row). The
console does not use `use cache`, `unstable_cache`, Cache Components or the
Edge runtime (checked on `main`), but it serves `/api` through Next's
self-hosted proxy rewrite (`next.config.ts`) and uses `next/image`, so
GHSA-pc58-hwjq-p385 and GHSA-7qx7-33qx-rqx2 may apply. 16.4.6 is the latest
patch.

## Decisions

1. Pin `next` and `eslint-config-next` to `16.4.6` exactly (as today, no
   range). No other dependency moves; `bun.lock` changes only for those two
   and what they pull in.
2. The lockfile is written with the CI's bun, **1.3.12** (`packageManager`,
   `ci.yml`), not the VM's 1.4.0: run `npx -y @oven/bun-linux-x64@1.3.12`'s
   `bin/bun install` (or an equivalent 1.3.12 binary) so the lockfile
   format does not change.
3. Check the changelog between 16.4.3 and 16.4.6 for anything touching the
   `/api` rewrite proxy (`proxyClientMaxBodySize`, `proxyTimeout`,
   `experimental` keys in `next.config.ts`) and say what you found in the
   handoff.

## Checks

`bun x tsc --noEmit -p .`, `bun x eslint next.config.ts src/app`, and the
test files under `src/app` (wrapped in the memory limit). `next build` is not
run on the VM; CI builds it. CHANGELOG entry under Security.

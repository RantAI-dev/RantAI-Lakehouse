## Why

Dependabot has four open alerts on `main` since 2026-10-06 for `pymongo`
4.9.2 (`dagster/pyproject.toml`): GHSA-v4x9-3549-crwv (high, heap
out-of-bounds write in BSON encoding), GHSA-vp6j-j7w5-5xjj (high, host
injection through percent-encoded delimiters in a connection string),
GHSA-qx36-8mw2-4r3x and GHSA-8fvv-fgr5-f8ch (moderate). 4.18.2 fixes all
four; it ships a cp312 manylinux x86_64 wheel and needs Python >= 3.9
(PyPI, checked 2026-10-24). Our adapter passes hosts and credentials as
keyword arguments, never as a URI string
(`dagster/dispar_orchestrate/adapters/mongodb.py:136-153`), so the host
injection is less reachable, but BSON encoding runs on every document.

## Decisions (planner)

1. `dagster/pyproject.toml`: `"pymongo==4.18.2"`. Rewrite the comment above
   the Tier 2 adapter pins so it is true: it says newer releases exist and
   these pins are kept without a reason; now `pymongo` moves for `SEC-52`
   (name the four GHSA ids), checked installable for `python:3.12-slim`
   on 2026-10-24. `oracledb` and `paramiko` stay as they are (out of
   scope; `paramiko`'s low alert has no fixed release).
2. Nothing else pins `pymongo` (the vendored `requirements.txt` files are
   for other sources); grep to confirm and say so in the handoff.
3. Behaviour must not change. Read the `pymongo` changelog between 4.9.2
   and 4.18.2 for removals or changed defaults that touch what
   `adapters/mongodb.py`, `discover.py`, `column_gate.py` and
   `ingest_errors.py` use (`MongoClient` keyword arguments,
   `directConnection`, `OperationFailure.code`, error class names, BSON
   type decoding, the resolver hook `ssrf_guard` wraps). List what you
   checked. If something we use changed, stop and report.

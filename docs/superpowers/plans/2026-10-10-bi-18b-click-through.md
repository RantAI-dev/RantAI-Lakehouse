## 1. Decisions already made (do not re-ask, do not change)

| Decision | Choice |
| --- | --- |
| Records | One route for marts and SQL sources. Rows go through the same guard and role rewrite as the tile's own query. Paged: `limit` (default and maximum 50) and `offset`; the response carries `total`. The dashboard's active filters are applied with the builder's `filter_predicates`, not a second implementation. A SQL source keeps its own row cap. |
| What a click means, per kind | category charts: the category (today). `geomap`: the region's stored value (the row's own value, not the normalised map name). `pointmap` / `geoheat`: the point's label column when the chart has one, otherwise no value drill. `calendar`: the day. `sankey` / `sunburst`: the clicked node's value in its own column (`x` or the breakdown). `boxplot`: the category. `kpi`, `gauge`, `table`: no value; the tile's menu offers "View records" for the whole tile. `text`: nothing. Time-series axes that are a derived period keep having no value drill; say so in the code. |
| Click setting | Optional `click` on the chart spec and input, absent on every chart saved before (absent = the drill menu). Shapes: `{ "kind": "dashboard", "board": "<id>", "column": "<name>" }`, `{ "kind": "query", "id": "<saved query id>" }`, `{ "kind": "url", "url": "<template>" }`. The template's placeholder is `{value}`. Server validates shape and size only, plus the URL rule below; it does not check that the board, column or query exists (the console says so when it does not). |
| URL rule | Accepted: `https://…`, `http://…`, or a path starting with a single `/`. Anything else is refused at save, in particular `javascript:`, `data:`, `//host`, and a template that puts `{value}` in the scheme or host position. The console inserts the value with `encodeURIComponent`, opens an external URL in a new tab with `noopener noreferrer`, and navigates in-app for a path. |
| Destination dashboard | Opened at `/dashboards/<board>?f=<encoded filter>` with one `in` filter on the chosen column, using the existing encoder. |
| Auto-refresh | A saved interval on the board, seconds, one of `0, 60, 300, 600, 900, 1800, 3600`; other values refused. Written through the existing board write path (`dashboard:write`). The console starts from the saved value; a viewer's change is session-only. |
| Full screen | The Fullscreen API on the dashboard container, falling back to the existing in-page view when the API is unavailable or refused. A "Dark" toggle in full screen applies the dark theme to the dashboard only, remembered in `localStorage` (a per-viewer convenience; try/catch). |
| Embeds and public links | Unchanged: no click menu, no destinations. |
| Storage | No migration unless the board's or chart's store truly needs a new column; boards live in `ClickHouse` `console.bi_board` (see how `SEC-12` added columns in `ensure_bi_table`) and chart specs are JSON. |

## 3. Tasks

One commit per task; Rust first.

### T1 — Records: paged, filtered, SQL sources

Extend the records route (same route, same policy): `limit`, `offset`,
`filters` (validated with part A's validator), an optional `sqlSource` id
instead of `mart`, and a value-less form for a whole tile. Build the row
query with the builder's relation and predicate machinery so a mart and a
SQL source share one path and the active filters mean exactly what they
mean on the tile. Return `{ columns, rows, total, limit, offset }`. `total`
is a separate count through the same rewrite. Keep `supported: false` only
for what truly cannot be listed, with the reason.

*Accept:* route tests in the file's style: a mart and a SQL source each
return a page and a total; `offset` pages; a limit over 50 is clamped; the
active filters are in both the row and the count query; a masked column is
masked (extend the existing enforcement test); a column the relation lacks
is a 400 with our message; the value is a bound literal (a value with a
quote and a backslash is tested through the route). Because mock-only tests
have missed real-engine failures twice on this branch: run the generated
row and count statements once against the dev `ClickHouse` (read-only,
`serving.mart_demo_map_points`) for a mart and for a subquery standing in
for a SQL source, and quote the commands and counts in the handoff.

### T2 — Click setting and saved refresh (server)

`click` on `ChartSpec` / `ChartInput` with validation as in section 1 (a
pure, tested URL-template check); the board's saved refresh interval with
validation; both through the existing write routes; both returned where the
console reads charts and boards. Assistant schemas for `create_chart` /
`update_chart` gain `click`; regenerate the fixture.

*Accept:* unit tests for the URL rule (each refused form in section 1, and
the accepted ones); old chart and board rows deserialise unchanged and
serialise without the new keys; an interval outside the list is a 400.

### T3 — Console: click on every kind

Read the click from each chart kind as section 1 says and feed the existing
click menu (View records, Filter). Whole-tile "View records" in the tile
menu for KPI, gauge and table. Remove kinds from `drillColumn`'s exclusion
only as they gain a real value; keep the comment true.

*Accept:* a pure function mapping (kind, spec, click event payload) to the
drill target, with tests per kind including "no value" cases.

### T4 — Console: records dialog

Paging (Previous / Next, "1–50 of N"), the total, the active filters
passed along, SQL-source charts supported. Loading and error states use the
`SEC-11` idiom (`ErrorWithReference`).

*Accept:* component tests for paging and the empty and error states.

### T5 — Console: click destinations

Chart builder: an "On click" control (Drill menu / Open dashboard / Open
saved query / Open URL) with the fields each needs (board select + column
select from that board's `filterFields`, saved-query select, URL input with
a one-line hint about `{value}`). Compact: the owner asked for less text in
dialogs; one line of help at most. Dashboard: a tile whose chart has a
destination performs it on click (a small cue on hover that the chart is
clickable), with the drill menu still reachable from the tile menu. Pure
helpers for building the destination (`/dashboards/<id>?f=…`, the URL with
the encoded value) with tests, including values with spaces, `&`, `#`, `/`
and non-ASCII.

### T6 — Console: saved auto-refresh and real full screen

The refresh menu shows the saved default and, for an editor, "Save as
dashboard default". Full screen through the Fullscreen API with the
fallback and the Dark toggle of section 1.

*Accept:* unit tests for the interval logic and the fullscreen fallback
decision (the API mocked).

**Deviations from the plan (all small; each for you to accept or reverse)**

1. Full screen is requested on `document.documentElement`, not on the dashboard container. Reason: under an element's full screen the browser renders only that element's subtree, and the console's menus, dialogs and tooltips are portalled to `<body>`, so the "..." menu (the way out) and the records dialog would vanish. The in-page overlay is always applied; the API is added on top; a refusal gives a toast "Showing the dashboard in the page". The Dark switch themes the container only (a `dark` class on it); portalled content keeps the console's theme.
2. `refreshSeconds` is accepted on the built-in Main dashboard too (`board_edit_allowed` only forbids the fields listed there); filters cannot be saved on Main, a refresh is a view setting like its layout.
3. A click on a `text` tile is refused at save ("a text tile has nothing to click."); the builder shows no click control for text, KPI, gauge, table or geo heat (no marks to click).
4. "View records" for the whole tile is also offered on a geo heat map tile (otherwise its rows cannot be listed at all).
5. The old `source` query parameter of `/records` is kept as a serde alias of `sqlSource` (it was never sent by the console); the old "not supported for SQL sources" answer is gone with its test (replaced by SQL-source tests).
6. The sunburst gets `nodeClick: false` (default zooms the ring in on click, which would fight the drill menu).
7. The destination dashboard's column list comes from `GET /api/dashboard?board=<id>` (its `filterFields`), which runs that board's tiles each time a destination board is chosen in the chart builder; there is no lighter route and I added none.
8. The former "Every 30s" auto-refresh choice is removed (the server refuses 30); intervals are the list above.
9. The click setting is not copied into the chart's rendered `spec` JSON of the dashboard payload; the console reads it from `def.click`. Embeds are sent `def` without `click`.
10. A saved query's existence is not checked in the console (no id lookup route); the picker lists saved queries and marks a saved id that is no longer in the list. A deleted destination dashboard is checked against the board list at click time and says so.

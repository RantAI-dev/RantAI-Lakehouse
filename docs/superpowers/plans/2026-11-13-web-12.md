### 0.1 The one sentence (S1, `src/services/errors.ts`, unchanged by this slice)

`deniedFor(status, body)` returns `null` unless the status is 401 or 403. For a 401 or a 403
it returns `new ServiceError("permission_denied", message, status, undefined, detail)`, where
`message` and `detail` come from `readDenied(body.error)`:

| API `error` | `message` |
| --- | --- |
| `permission_denied: dashboard:write` | You don't have access. This needs the dashboard:write permission. |
| `permission_denied: assistant:use, assistant:ask` | You don't have access. This needs one of these permissions: assistant:use, assistant:ask. |
| `permission_denied: Downloads are switched off for your role.` | Downloads are switched off for your role. |
| `permission_denied: manage on this item` | You don't have access. Reason given: manage on this item. |
| `forbidden`, `unauthorized`, no body, not JSON | You don't have access. |
| `You do not have permission to do this.` (words, no code) | unchanged, as sent |

The pattern every S1 client follows (for example `src/services/clients/metrics.ts:17-26`,
which #504 already moved):

```ts
if (!res.ok) {
  const denied = deniedFor(res.status, json)
  if (denied) throw denied
  // … the client's own table for every other status, unchanged
}
```

`src/services/clients/assets.ts:20-35` shows the other pattern, for a client with a private
`errorFor(status, message)`. The signature becomes `errorFor(status, body, fallback)`, it asks
`deniedFor` first, and each call site passes the body and its fallback text.

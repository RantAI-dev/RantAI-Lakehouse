## T1 `SEC-45`: an approver can only approve a permission they hold

- **Gap.** `A/routes/catalog.rs:3489` `decide_access_request` refuses
  self-approval (`:3549`) but never checks that the decider holds the
  permission the request asks for. `#106` closed the same gap for direct
  grants: `A/routes/catalog_grants.rs:147-153` (`if !principal.has(permission)`
  → `ApiError::PermissionDenied("you cannot grant a permission you do not hold")`).
- **Decision.** Approving (not rejecting) a request needs
  `principal.has(<requested permission>)`; otherwise a fixed 403 with the
  same sentence shape ("you cannot approve a permission you do not hold"),
  checked before any write and before the audit row, so a refused approval
  changes nothing. Rejecting stays allowed (it gives nothing). Reuse the
  existing check; do not write a second helper (rule 4).
- **Check.** Route tests: a custom role with `access:approve` but not the
  requested permission gets 403 and the request stays pending; with the
  permission it is approved; rejecting without it still works. Each fails
  without the fix. `cargo test -p lakehouse-api` filtered to the new tests
  plus `tests/route_auth.rs`.

## T2 `SEC-37`: no default credentials left in code

- **Where.** `ops/g3/g3_loadgen.py:112-113` and
  `dagster/dispar_orchestrate/dlt_pipeline.py:155-156` fall back to
  `rustfsadmin`; the backlog also names `ops/g6/g6_ingest_matrix_test.py`
  (grep it); `A/config.rs:543,1387-1388` default `DATABASE_URL` to
  `postgres://lakehouse:lakehouse@localhost:5432/lakehouse`.
- **Decision.** Fail closed (principle 3): no fallback value. Python reads
  the variable as required and raises a clear configuration error naming the
  variable (Dagster: `Failure` for config, per the Python rules); the gate
  scripts exit with the same kind of message. Rust: `DATABASE_URL` unset
  means "no Postgres pool" (the path `main.rs:118` already handles with a
  warning), not a made-up URL; update the field's doc and the tests at
  `config.rs:1579-1627` that assert the default. Compose and
  `.env.example` already set every one (verify with grep; if one is
  missing, stop and report).
- **Check.** grep shows no `rustfsadmin` or `lakehouse:lakehouse` literal
  left outside tests and docs that name it as forbidden; unit tests for the
  missing-variable error in Python and for `DATABASE_URL` unset in Rust;
  `docker compose --profile '*' config --quiet` with the must-set vars;
  gitleaks clean.

## T3 `SEC-25`: connector security follow-ups

- **(a) A connector with no credential can never be re-pointed.**
  `A/routes/connectors.rs:1611-1640` (`REPOINT_NEEDS_CREDENTIALS`,
  `credential_slots_read`, the coverage check after it): Kafka with auth
  `none` reads 0 slots, yet a re-point answers 409 without credentials and
  400 with one. Decision: a re-point of a connector whose new dial reads 0
  credential slots needs none and is allowed (nothing secret can be sent to
  the new host); every other case is unchanged. Test both ways (Kafka
  `none` re-points; Kafka with SASL still needs its credentials).
- **(b) The PATCH-`host` rule for `files` connectors** (`A/routes/connectors.rs:437`
  `dials_from_host`, and its doc) predates `SRC-6`. Read what a `files`
  connector dials today; make the rule and its doc say that, with a test.
  If the rule is right and only the doc is stale, change the doc only, and
  say so in the commit.
- **(c) The `SEC-15` refusal message has runs of spaces** (a `\` line
  continuation inside a string literal near `A/routes/connectors.rs:2950-3125`).
  Fix the literal so the text has single spaces; a test asserting the exact
  text.

  with "Error while loading rule 'react/display-name':
  contextOrFilename.getFilename is not a function": eslint 10 removed the

  last release) still calls it. That run used `eslint-config-next` 16.1.6.
- Public reports (not verified here): `eslint-config-next` 16.4.0 patches
  the removed rule-context members in place for the plugins it bundles, and
  Next's docs state it supports eslint 9 and 10; some bundled plugins still
  do not list eslint 10 in their peer ranges.

## 2. Decisions

- D1. Target the newest `eslint` 10.x, caret range as now (`^10`).
- D2. Keep `eslint-config-next` at what `main` has; do not add a plugin,
  remove a rule, or disable a rule set to make eslint 10 run (rule 2). If
  lint cannot run on eslint 10 without that, stop and report: `REL-5`
  stays blocked on upstream, as `REL-4` is.
- D3. A peer-dependency warning from a bundled plugin is acceptable if
  `bun install --frozen-lockfile` and lint both succeed; record it.
- D4. The lint result must not get weaker: 0 errors, and no more warnings
  than today (8), and the rule set that runs is the same (compare
  `bunx eslint --print-config src/app/page.tsx` before and after; the rule
  names and severities must match, apart from rules eslint 10 itself
  renamed or removed, each listed with its eslint 10 changelog line).

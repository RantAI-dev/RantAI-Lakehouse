## 0. What is wrong, with evidence (re-read at `c7cd01a76`)

QA evidence is the base's QA table (`Findings` of each case); the code anchors are below.

### AI-28: approval of an assistant action

1. **A recorded decision answers 403** (`LH-AI-18-07`). `decide_approval`
   (`rust/crates/lakehouse-api/src/routes/agents.rs:708`) flips the approval to `approved`
   (`:750`), writes the decision's audit row (`:771-779`), then checks the approver's own
   permission for the tool (`:844-845`) and, when it is missing, records the run `failed` and
   returns `ApiError::PermissionDenied` (`:870`). The console's Approvals page wraps the call in
   `withNotify({ success: "Decision recorded", error: "Failed to record decision" })`
   (`src/features/agents/approvals-page.tsx:234-240`), so a decision that was recorded shows
   "Failed to record decision". Feature decision 5 (`copilot-chat.md`, ADR 0012 decision 3,
   signed) says "the decision is recorded and the action does not run": the answer must say
   that, not fail.
2. **A reopened conversation shows a decided approval as pending** (`LH-AI-18-09`). A
   `WriteHigh` step stores `{needs_approval: true, approval_id, run_id, summary}`
   (`routes/ai/gate.rs:377-383`) in the conversation. `loadSession`
   (`src/features/copilot/use-copilot.ts:618-635`) restores the messages as saved, and
   `ToolStepCard` (`tool-step.tsx:513-570`) marks every `needs_approval` step "pending approval"
   (`:558-560`) with "Someone else with approval rights must approve it." (`StepBody`,
   `:254-271`). Nothing reads the run's state again.
3. **A refused self-approval (403) and a second decision (409) write no audit row**
   (`LH-AI-18-10`). The self-approval check returns before any write (`agents.rs:741-745`; the
   doc comment of `refuse_own_request`, `:568-572`, says so on purpose), and the 409 returns at
   `:755-759`. The route is `Coverage::Handler` (`audit_coverage.rs:437`), so the central writer
   does not cover it. Feature decision 6: "One immutable row per gate decision".

### AI-29: a target parameter drawn as a line (`LH-BI-11-07`, Fail)

The tester asked to add a target line on a chart whose existing line was bound to the `target`
parameter. The assistant called `format_chart` with `referenceLines: [{value: 20000, label:
"Target"}]`. `merge_format` (`routes/ai/tools/look.rs:95-145`) replaces each field it is given
(`:127-137`), so the bound line was dropped and the chart stopped following the parameter; no
parameter was created. The build prompt's own example teaches exactly that call
(`routes/ai/prompt.rs:543`: "add a target line at 1,000 … referenceLines ([{value: 1000, label:
\"Target\"}])"), and its parameter sentence ("to draw a target line, create a number parameter
and pass it in referenceLines", same line) does not say the list replaces the lines already
there. The tool has no way to add one line and keep the others.

### AI-30: subscriptions and exports (`LH-RPT-1-08`, `LH-RPT-1-09`, `LH-BI-1-07`)

1. **A colleague cannot be found.** The tools have no lookup of the installation's people; the
   schema offers `recipients[].userId` "a console user's id" with no way to learn one
   (`registry.rs:1892-1895`). The console's own picker exists:
   `GET /api/reports/recipients?q=` (`routes/reports.rs:996-1053`, `PickerQuery` at `:985`),
   which asks `dashboard:read` and the download right and is scoped to the caller's tenants.
2. **After a refusal the requested recipient is dropped.** The model offered a report for the
   person alone. Nothing in the prompt (`prompt.rs:543`, the report sentences) says what to do
   when a recipient is refused.
3. **The PDF leaves out the active filters.** `export_dashboard` puts `filters` in the link only
   when the call sends them (`tools/export.rs:97-108`, `:311-323`). The prompt asks the model to
   copy them from the page context (`prompt.rs:543`), which is free text
   (`routes/ai/mod.rs:405-420`); the model did not. The chat request carries no structured view
   of the dashboard on screen (`ChatBody`, `mod.rs:295-308`).
4. **The download link is shown as raw Markdown.** `tokenizeInline`
   (`src/lib/citation-markers.ts:52-55`) renders a link only for `https?://`; the export URL is
   relative (`/api/dashboard/export/pdf?…`), so `[Download](/api/dashboard/…)` stays as text,
   next to the Download button the card already shows (`tool-step.tsx:121-129`).

### AI-31: what the assistant writes

1. **After Confirm the reply still says it waits** (`LH-AI-18-02`, `LH-BI-13-05` F2). The
   console adds a `Saved:` line (#392, `saved-status.tsx`), but the reply text stays. The
   prompt asks for "ONE short sentence that names the draft" (`prompt.rs:558`) and does not
   forbid a sentence that stops being true once the person confirms ("Konfirmasi di bawah…").
2. **A refusal names the technical permission and the dashboard's id** (`LH-BI-11-04` F1,
   `LH-BI-13-02` F1). The permission note tells the model to "write dashboard:write exactly as

3. **Confirmation and approval cards are Indonesian in an English console** (`LH-RPT-1-08` F2,
   `LH-RPT-1-09` F4). Every sentence a card shows is built in `gate.rs`: `summary_for`
   (`:577`), `pipeline_summary` (`:415`), `look_summary` (`:448`), `board_layout_summary`
   (`:485`), `report_summary` (`:505`), `alert_summary` (`:530`), `reason_for_write_high`
   (`:128`), `embed_write_high_reason` (`:204`) and the five risk constants (`:258-301`). The
   console has no other language.
4. **A draft card does not mention the chart's second question** (`LH-BI-13-05` F1).

   (`src/features/copilot/chart-draft-card.tsx:262-271`), and the `create_chart` summary
   (`gate.rs:585-597`) names one source.

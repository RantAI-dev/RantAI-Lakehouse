## 1. Decisions already made (do not re-ask, do not change)

The feature page's table, plus these build decisions.

- **D1 Gotenberg in compose.** A `gotenberg` service, image
  `gotenberg/gotenberg:8.<x>` pinned to an exact tag (the developer picks
  the newest 8.x tag at least two weeks old and records it), no `ports:`
  (reached by service name only, like `openfga`; copy its comment's
  reasoning), `restart: unless-stopped`, a memory limit of 1 GiB, and
  command flags: `--api-timeout=70s`, `--chromium-allow-list` set to a
  regex that matches only `CONSOLE_INTERNAL_URL` (so the renderer can open
  nothing else: decision 3), `--chromium-disable-javascript=false`,
  `--log-level=warn`. No profile: it is part of the default stack. The
  `lakehouse-api` service gets `GOTENBERG_URL: ${GOTENBERG_URL:-http://gotenberg:3000}`
  and `CONSOLE_INTERNAL_URL: ${CONSOLE_INTERNAL_URL:-}` (the console is not
  in compose; staging runs it as `lakehouse-frontend:3000` on the compose
  network, `.github/workflows/deploy-staging.yml`, so the staging deploy
  sets `CONSOLE_INTERNAL_URL=http://lakehouse-frontend:3000`). Either unset
  or empty → PDF is unsupported (feature decision 6). `.env.example` gains
  both with an explanation and no credentials.
- **D2 Render token.** In `lakehouse-embed` beside `EmbedClaims`:
  `RenderClaims { aud: "render", board, principal, filters, params, paper,
  orientation, exp, iat, jti }`, signed with a key derived from
  `EMBED_SECRET` with a fixed domain label (HMAC of the label under the
  secret), so an embed token never verifies as a render token and the
  reverse (test both). Lifetime 120 seconds (feature decision 2), not
  configurable. `EMBED_SECRET` unset → PDF unsupported.
- **D3 Render data route.** `POST /api/render/data { token }`, classified in
  `POLICY_TABLE` as public (token-authenticated, like `/api/embed/data`) and
  asserted both ways in `tests/route_auth.rs`. It verifies the token, loads
  the principal by id from the identity store with their current roles (a
  disabled or deleted user → refused), builds the `Viewer` for that person
  (so their own personal-space board prints), and answers the same payload
  the dashboard page gets, for **every** tab, with the token's filters and
  parameters, read through the same masking path as the dashboard page for
  that person (`rewrite_sql_for_principal` / `rewrite_sql_for_roles`, not
  `EMBED_VIEWER_ROLE`). No session cookie is accepted on this route.
  Errors are classified (SEC-11).
- **D4 Print view.** `src/app/render/dashboard/[token]/page.tsx`, outside the
  app shell. It posts the token to `/api/render/data`, renders every tab in
  order (a page break before each tab after the first, the tab title as a
  heading), sections unfolded, the header block of feature decision 4, image
  and web cards as the placeholder of feature decision 3, ECharts with
  animation off, the dashboard's theme and font (`BI-17` A), and sets
  `window.__lakehouseRenderReady = true` once every tile has drawn or shown
  its error. `src/proxy.ts` matches `/render/:path*` too and sends
  `frame-ancestors 'none'`, `Cache-Control: no-store`, `Referrer-Policy:
  no-referrer`, `X-Robots-Tag: noindex`.
- **D5 PDF route.** `GET /api/dashboard/export/pdf?board=&paper=a4|letter&orientation=portrait|landscape`
  plus the dashboard's filter and parameter query string as the page uses
  it. Needs `dashboard:read`, the board visible to the person, and
  downloads allowed (D7). It mints the token and calls Gotenberg
  `POST {GOTENBERG_URL}/forms/chromium/convert/url` (multipart: `url`,
  paper size, `landscape`, margins, `printBackground`, `emulatedMediaType=print`,
  `waitForExpression=window.__lakehouseRenderReady === true`, a footer HTML
  with page numbers). Its `reqwest` client: 70-second total timeout, no
  redirects, no proxy; the URL comes from configuration, never from the
  request (say so at the site, as for the Dagster and Lakekeeper clients).
  At most 2 at once per process (a `tokio::sync::Semaphore` in `AppState`);
  the third waits. Failures answer fixed sentences through `upstream_error`
  (timeout: "The PDF took too long to make."; Gotenberg down: "The PDF
  service is not reachable."), never Gotenberg's text. The audit record is
  written before the file is sent (D8). File name: the board name made
  safe, plus the date.
- **D6 Data export.** `GET /api/dashboard/chart-export?chart=&format=xlsx|csv&values=formatted|raw`
  plus filters and parameters, for every chart kind that has rows (not
  static kinds). A raw table exports its whole result up to 1,000,000 rows,
  a grouped chart its own result. The statement is the one the tile reads
  (or `table_export`'s `export_statement` for a raw table), through the same
  rewrite. Over a SQL source a separate export settings path lifts the
  tile's `max_result_rows = 2000` to the export cap (+1 to detect a cut),
  not by changing `SQL_SOURCE_SETTINGS`. Rows are **streamed**: a new
  `ChClient` method reads `JSONEachRow` line by line with a 300-second
  timeout; CSV is written to the response as rows arrive; XLSX is written
  with `rust_xlsxwriter` in constant-memory mode to a temporary file
  (deleted after sending, and on every error path) and then streamed.
  Formula neutralising is shared with `csv_export.rs` (one helper, rule 4).
  "Formatted" maps a `BI-17` value format to an Excel number format string
  (currency symbol, decimals, thousands, percent, compact via a scaled
  custom format) and, for CSV, to the text the chart shows. The existing
  `table-export` route stays and calls the same code. Headers
  `X-Export-Rows`, `X-Export-Cut`, `X-Export-Cap` as today. New dependency
  `rust_xlsxwriter`, pinned; `cargo deny check` and `cargo audit` must pass
  with it (a PR that touches dependencies must not merge with them red).
- **D7 Download roles.** Migration `rust/migrations/0087_download_roles.sql`
  (why-header): `reporting_settings` gains `download_denied_roles TEXT[] NOT
  NULL DEFAULT '{}'`. `put_reporting` accepts role names that exist. One
  helper `may_download(principal, settings)` (Platform Admin always may; else
  at least one of the person's roles not in the list) is called by the PDF
  route, the chart export, the table export and the assistant tools; the
  dashboard payload carries `canDownload` so the console hides the items.
  Admin > Settings gains a "Downloads" section (a checkbox per role).
- **D8 Audit.** The existing `record_export_audit` pattern for every download
  (actions `dashboard.pdf_export`, `dashboard.chart_export`), refused when
  the audit store is down.
- **D9 Assistant (AI-10, export half).** Tools `export_dashboard` and
  `export_chart` (ReadOnly risk class) return `{ url, fileName }` pointing at
  the D5/D6 routes with the arguments; nothing is generated until the
  person opens it. Refused with the console's sentence when downloads are
  off for the person or PDF is unsupported. Named in
  `src/features/copilot/capabilities.ts`; the chat renders the link as a
  download button; prompt line; fixture regenerated with the ignored writer
  test; count pin +2.
